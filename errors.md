# Common errors

| Error | Cause |
|-------|-------|
| `Duplicate field 'X' in document literal.` | `DUPLICATE_NAME`: the same field name, ignoring case, appears twice in one INSERT document, nested object or SUBTYPE literal, or UPDATE / REPLACE / ON CONFLICT SET list |
| `Field 'X' does not exist in schema for collection 'Y'` | INSERT / UPDATE SET references an unknown field name |
| `Cannot SET document literal for field 'X' (type T)` | Type mismatch — document literal `(...)` used for a scalar field |
| `Cannot update primary key field 'X'` | UPDATE SET tries to modify the PK field |
| `SUBTYPE clause is not valid for non-polymorphic collection` | SUBTYPE used on a non-polymorphic collection |
| `Unknown subtype 'X'. Known subtypes: ...` | INSERT SUBTYPE, WHERE `SUBTYPE IS / IN` over a collection or a CTE, derived or joined input, partial-index WHERE, or a CHECK (`INVALID_DEFINITION`) names a subtype the relation or object doesn't declare |
| `Polymorphic collection requires SUBTYPE clause on INSERT` | INSERT on polymorphic collection without SUBTYPE |
| `Expected subtype name in square brackets (e.g., [Car])` | Quoted string (or other non-identifier) where a subtype name belongs — names are bracketed identifiers |
| `SUBTYPE is tested with IS / IS NOT / IN` | `SUBTYPE = ...` comparison form in WHERE — use `SUBTYPE IS [Name]` |
| `SUBTYPE IS NULL is not valid` | Every document in a polymorphic collection has a subtype; use `IS [Name]` / `IS NOT [Name]` |
| `DDL requires migration context. Use BEGIN MIGRATION / COMMIT MIGRATION.` | DDL executed outside a migration block |
| `A transaction is already in progress` | Nested transaction attempt |
| `No transaction in progress` | COMMIT / ROLLBACK without BEGIN |
| `MIGRATION_IN_PROGRESS` | Another session owns this database's migration; retry the original expected level after it finishes |
| `Schema level mismatch: expected X but database is at Y` | BEGIN MIGRATION with wrong fromLevel (`SCHEMA_LEVEL_MISMATCH`) |
| `Column 'X' does not exist. Available columns: Y, Z, ...` | SELECT references a non-existent field |
| `Value 'X' is in use by collection 'Y'. Provide a REPLACE value.` | ALTER ENUM REMOVE VALUE when the value is in use (`OBJECT_IN_USE`) |
| `SUBSCRIBE requires a server connection context` | SUBSCRIBE used outside TCP server (`FEATURE_NOT_SUPPORTED`) |
| `MQL string literal at position N contains a NUL ('\0') character` | NUL byte embedded in a `'...'` literal — reserved as the internal `IN`-list separator. Use a [parameter](parameters.md) instead so the value rides the binary protocol byte-for-byte. |
| `DOCUMENT_SEALED` | A logical row mutation targeted a sealed identity. Run `UNSEAL` explicitly before retrying. `ON CONFLICT DO NOTHING` remains allowed because it performs no mutation. |
| `Cannot SEAL identity ... timeline has an absence ...` | A retained FK with Cascade/SetNull would schedule a later mutation into the sealed identity (`OBJECT_NOT_IN_PREREQUISITE_STATE`). Make the referenced temporal timeline continuous, change the FK action, or leave the row unsealed. The same preflight applies when an FK is added to existing sealed rows. |

## Classified-error surface

Policy-relevant detector, health, and boundary errors use a stable `(Class, Code)` pair drawn from a curated registry. The registered list is queryable at runtime as a virtual system collection; operators should treat that registry as the source of truth rather than grepping engine source:

```mql
FROM [Mnemic].[ErrorCatalog] SELECT [Class], [Code], [Description];
FROM [Mnemic].[ErrorCatalog] WHERE [Class] = 'StructuralCorruption'
                              SELECT [Code], [Description];
FROM [Mnemic].[ErrorCatalog] WHERE [Code] = 'PAGE_CHECKSUM' SELECT [Description];
FROM [Mnemic].[ErrorCatalog] WHERE [Class] = 'User' SELECT [Code], [Description];
```

Ordinary mistakes in a statement are `User`-class errors with a specific code, modelled on the PostgreSQL SQLSTATE for the same condition. None of them is retryable unchanged; correct the statement, its parameters, or the session state first.

The server adds three connection-level codes: `AUTHENTICATION_FAILED` (28P01; missing or rejected credentials, without saying which), `AUTHENTICATION_REQUIRED` (class 28; a statement before Connect), and `NO_DATABASE_SELECTED` (3D000; a database-scoped statement on a server-level connection), plus the retryable `Transient / DATABASE_DROP_IN_PROGRESS` for a connect, `CREATE DATABASE`, `DROP DATABASE`, or `REOPEN DATABASE` naming a database whose drop has not finished removing its files, and `Cancellation / SESSION_TERMINATED` (57P01 analogue) for every request of a session the server ended because its database was dropped, closed (as `REOPEN DATABASE` closes it), or shut down; the server closes that connection, so open a new one ([database management](databases.md)). Missing collections report `COLLECTION_NOT_FOUND` (42P01), and so does the `SubscriptionEnded` frame of a change subscription the server ended because a committed drop removed the collection it watches or a relation its filter reads ([subscriptions](subscriptions.md#a-committed-drop-ends-the-subscription)); names in the `[Mnemic]` namespace report `RESERVED_NAMESPACE`. Write conflicts between concurrent transactions are the retryable `Conflict` class: `TX_CONFLICT_FWW` when another transaction committed a write to the same row after this transaction's snapshot (first writer wins), and `TX_CONFLICT_SERIALIZABLE` when a collection a serializable transaction read changed after its read; retry the whole transaction ([transactions](transactions.md)). Removing an Internal attribution actor that CreatedBy still references, by DELETE or by a materialized view replacement or maintenance that drops its key, reports `CREATEDBY_ACTOR_REFERENCED`.

A programmatically built AST is held to the same rules as parsed text and reports the same pair, whichever consumer meets it first — execution, EXPLAIN, expression evaluation, the server's subscription handling, or the canonical printer (`MqlPrinter`), which throws the classified exception rather than printing unparseable text. A definition, query, or DML clause list past a parser bound (ORDER BY, GROUP BY, JOIN, SELECT, WITH, WINDOW, IN, CASE, function-argument, document, RETURNING, or array-literal entries, or expression and query nesting) reports `LIMIT_EXCEEDED`; a value outside its clause's domain (a LIMIT or SKIP literal, NEAREST TOP or SEARCH_LIST, a session or `OPTION` statement timeout, an `OPTION` MAXDOP, a `VECTOR(n)` dimension, a negative window frame offset, a non-positive defragment budget, a non-finite admission watermark, an EXTERNAL CREATEDBY size below one) reports `INVALID_VALUE`; a negative index expiry lifetime reports `INVALID_DEFINITION`, as the index definition's own rule; a window function call of a name that is no window function MQL supports reports `UNKNOWN_FUNCTION`, and one with another number of arguments than its function takes `ARITY_MISMATCH`, as their text does; and an empty required list or any other shape violation is `INVALID_STATEMENT`, including a DDL definition with no schema, with a payload that belongs to another action, with a persisted body that differs from its executable form, or with an identity MQL cannot address, an `OPTION` clause wrapping another, an `EXPLAIN` without a statement, an undefined enumeration member (EXPLAIN format, isolation level, trigger timing or event, refresh mode, index action, CREATEDBY mode), a CREATEDBY payload of another mode, `ALTER ENGINE SET ADMISSION` without a setting, a point-in-time `RESTORE` without a target, and a `SUBSCRIBE` or `UNSUBSCRIBE` whose collection, WHERE, document or subscription-ID arms do not fit together. Definition text the AST carries for persistence (a computed column, CHECK, view, or trigger body) reports `LIMIT_EXCEEDED` past a parser bound and `INVALID_STATEMENT` when it does not parse.

The message text of each condition is unchanged and remains diagnostic only. EXPLAIN reports the same pair as executing the statement, and a validation rule that fails while rows are read throws the same pair. A failure that depends on the data read — an arithmetic failure while evaluating an expression (overflow, division by zero, invalid cast), an operand or argument whose kind is known only as the value is read (a CASE with arms of different types, text from a field compared by order with a date), a SUM or AVG accumulator overflow, a computed column whose value does not fit its declared type, or a scalar subquery with more than one row — reports the same pair whether it ends the statement or surfaces while rows stream: `INVALID_VALUE`, `TYPE_MISMATCH` or `CARDINALITY_VIOLATION`. In process the thrown exception carries the pair (`NumericEvaluationException` and `AggregateOverflowException` wrap the framework exception as their inner exception); remote clients receive it as `MqlException`. `TRY(expr)` recovers exactly the expression failures, not an aggregate overflow inside a subquery.

A revision or schema-level mismatch is not a retryable conflict: the statement names the stale revision or level itself, so the same statement fails again. Re-read the current value and decide. Transient migration contention keeps `MIGRATION_IN_PROGRESS` and `MIGRATION_CONFLICT`.

No error result is message-only. Refusals of engine and session state carry their own pair: a quarantined engine refuses with `StructuralCorruption / ENGINE_QUARANTINED`, its message naming the code of each fault that refuses the statement ([health](health.md#refusal-message-shape)); a `ReadOnly` engine refuses a mutation with `User / ENGINE_READ_ONLY` (25006) and a `Draining` one a new scope or an independently committed mutation with the retryable `Transient / ENGINE_DRAINING`; a plugin read gate or write guard vetoes with `User / PLUGIN_VETO`, listing every objection with its plugin id; `RESTORE` names a backup that does not exist with `User / BACKUP_NOT_FOUND` (58P01) and one that does not verify with `User / BACKUP_INVALID`; a `CASCADE` drop whose dependent view changed between computing its drop order and dropping it makes no changes and reports the retryable `Transient / CASCADE_PLAN_STALE`; and the server answers an unknown request opcode with `User / UNKNOWN_OPCODE` and an operation whose audit record could not persist under a strict audit policy with `Transient / AUDIT_UNAVAILABLE`. An engine-internal result that breaks its contract reports `ContractViolation` with its code: `NESTED_RESULT_SHAPE` (an internal statement returned the wrong shape), `PROJECTION_PLAN_INVALID`, `ENUM_DEFINITION_MISSING`. Only an exception no classifier branch maps reports `Internal / UNCLASSIFIED` (or `INTERNAL_ERROR` for a server handling failure), and client APIs preserve the pair when throwing `MqlException`. In process the failure itself travels too: an embedded engine's error result keeps the exception the statement failed with as its `Cause`, and the typed client's `MqlException` raises it as its inner exception, stack trace included, so a host without a logger still sees where a failure began ([health](health.md#where-a-fault-began)); the wire carries only the message and pair, so a remote client's `MqlException` has no inner exception and no engine stack. Do not infer retry policy from message text. `UNCLASSIFIED` is itself a cataloged fallback; it does not turn the original message into a stable catalog condition. The catalog also includes health-only signals, so a row does not imply that every occurrence is thrown as a statement error.

`HOOK_AFTERCOMMIT_FAILED` means the plugin callback failed after the committed outcome reached provider acknowledgement under the configured storage contract. That boundary is durable for durable providers; it is not a cross-process durability promise for the process-memory provider.

`HOOK_AFTERROLLBACK_FAILED` means a plugin's rollback-settlement callback failed after storage had already selected the non-commit outcome. The engine continues later hooks and keeps the transaction rolled back; the fault identifies plugin-side divergence and cannot turn the attempt into a commit.

`POST_COMMIT_CALLBACK_FAILED` and its per-callback health signal `HOOK_POSTCOMMITCALLBACK_FAILED` likewise describe a committed outcome, not a rollback. An implicit commit still attempts provider acknowledgement before the ordinary aggregate failure reaches its caller; the health signal alone is not a portable claim that bytes are on disk.

`DEADLOCK` means a cycle was observed among locks that explicitly participate in the waits-for detector, confirmed to have held all its edges at one instant, and this transaction was selected as the victim. The detector chooses the lowest current dirty-page count as a cheap work proxy and uses transaction identity to break ties. Detection follows the configured cadence; `LOCK_TIMEOUT` remains distinct because it proves only that one wait exceeded its deadline.

Classes have stable numeric ordinals where they cross the wire:

| Class | Meaning |
|---|---|
| `User` | Caller's bad input — invalid query, constraint violation, schema mismatch. Not retryable. |
| `Transient` | Temporary contention or backpressure. Caller should backoff and retry. |
| `Conflict` | Snapshot-isolation write-write conflict. A specific transient subclass with its own retry contract. |
| `Cancellation` | Statement was cancelled (timeout, user cancel, server shutdown, connection loss, database drop or close), or its session was terminated (`SESSION_TERMINATED`). |
| `Validation` | Schema- or constraint-level validation failure (distinct from `User` for callers wanting field-level diagnostics). |
| `ResourcePressure` | Memory / disk / connection budget exceeded. May be transient under load shedding. |
| `StructuralCorruption` | Corruption/integrity proof — quarantine trigger; ordinary MQL is refused until repair/resume or required reopen recovery, except that a lone `WAL_FLUSH_FAILED` retains bounded reads while refusing every mutation. |
| `ContractViolation` | Engine invariant violation ("shouldn't happen") — engine bug, surfaces a code + context for diagnosis. |
| `PluginFault` | A plugin hook threw or timed out. |
| `Internal` | Catch-all for unclassified exceptions surfaced through the engine boundary — treat as a bug. |

Structural-corruption classification survives execution wrappers. A detector raised directly or nested inside an aggregate/inner exception by an MQL interceptor, core handler, DDL observer, cleanup path, or lazy row stream keeps its stable corruption code and quarantines its exact fault domain; it is never downgraded to `UNCLASSIFIED` or a generic plugin error. The domain is diagnostic attribution, not selective admission: after a live structural report, ordinary MQL is refused. The sole code-specific exception is a lone `WAL_FLUSH_FAILED`, which retains bounded reads while the sealed writer refuses every mutation; any coexisting quarantine restores global refusal. An indeterminate in-flight append/fsync also publishes `WAL_WRITE_FAILED`, and an incomplete post-marker page apply also publishes `COMMIT_APPLY_FAILED_AFTER_MARKER`, so neither unsafe transaction state receives the read exception. `PAGE_CHECKSUM` identifies a page whose integrity trailer failed and follows that same global admission rule. `PAGE0_CHECKSUM` is different only in lifecycle: it means no usable current-format header slot remained, so open fails before a live engine or `[Mnemic].[Health]` row exists. Local validation, best-effort cleanup, and statement-specific error-conversion boundaries inspect the complete aggregate/inner exception graph before they handle a failure. A nested corruption proof therefore reaches the executor's quarantine path, and nested process-memory exhaustion is never converted into a routine local validation result or warning-only cleanup failure. Nested cancellation and simulated-crash signals likewise escape generic local conversion; all four classes reach the executor's terminal statement-failure boundary. Successful cleanup retries do not erase corruption or cancellation already reported by a resource owner. The owners can finish releasing while the statement still reports the authoritative failure. For `UNION`, `INTERSECT`, and `EXCEPT`, an ordinary input error or successful end-of-input cannot hide corruption or cancellation reported during result or branch cleanup. Hash-join and set-operation spill compactions defer only ordinary input-retirement failures. Direct or nested corruption, cancellation and memory exhaustion fail the statement while preserving independent causes and ownership for explicit disposal; a release failure cannot delete the published replacement run. Index bulk-load scratch writes preserve both the initiating write failure and a subsequent file-deletion failure, including their nested critical causes. Cleanup warnings cannot replace those causes. Memory exhaustion or modeled process death during warning delivery remains alongside them while independent cleanup finishes. Page allocation likewise retains its initiating failure alongside scratch-pool return faults; every independent buffer is still returned, including after memory exhaustion or modeled process death. Nontransactional allocation also retains failed live unpublished-page compensation alongside the initiating failure and any later scratch-return fault. This policy also covers session-parameter normalization and partial-index predicate compilation; their local user-error formatting is not allowed to consume a critical failure. Execution interceptors return `HOOK_EXECUTIONINTERCEPTOR_FAILED` only for ordinary plugin failures. Wrapped memory exhaustion and simulated-crash signals escape with their outer exception identity intact. An ordinary failure in the interceptor fault-attribution sink remains subordinate to that plugin error, but memory exhaustion or simulated process death from the sink escapes after any health transition already published. When an interceptor instead exposes structural corruption, ordinary failures in the corruption health reporter or logger cannot replace the detector's stable result. Memory exhaustion or simulated process death from either diagnostic surface escapes after any quarantine transition already published. The core statement funnel follows the same process-terminal rule after it has completed required statement poisoning and migration auto-rollback. If that rollback also fails, both failures escape in one aggregate instead of either being converted into an error result. Post-publication DDL observers still return `HOOK_DDLOBSERVER_FAILED` for ordinary replication or audit propagation failures, while wrapped memory exhaustion and simulated-crash signals escape after the local catalog change has committed and the observer fault has been attributed. Query-descriptor and result-schema shaping, plus DDL field, index, and rename adapters, follow the same rule: their `InvalidOperationException` compatibility catches convert only recoverable local failures. Cancellation is not an exception to this policy: a cancellation wrapper is rendered as `Statement cancelled` only when its complete inner exception graph contains no corruption proof, process-memory exhaustion, or simulated-crash signal. Statement-result validation after core dispatch remains inside the same health boundary, so a nested corruption proof quarantines its domain before the validation exception escapes to the caller.

`CATALOG_PUBLICATION_RETRY` is a `Transient` result, not a corruption signal. Atomic catalog publication cancelled a statement admitted against the retiring generation before it could resume with a stale descriptor. A statement its caller, deadline, an operator, connection loss, server shutdown or distributed creator cancelled first reports that cancellation instead. Retry the complete statement; the fresh execution binds the newly committed catalog generation. An in-process engine operation that yields to the same publication, such as a direct reverse-reference read, analysis, defragmentation or shrink, reports the same code. Only migration commit and structural DDL publications return it. Background reclamation of a replaced materialized-view generation waits for running statements instead and never cancels them.

`SCHEMA_GENERATION_CHANGED` is also a `Transient` result (SQLSTATE 40001 analogue, the retryable condition MySQL reports as "Table definition has changed"). A read the statement lowered against a collection's schema generation — a lazily read query stream, or a JOIN input's prepared primary-key probe — started after a catalog publication replaced that generation, so it failed closed instead of decoding rows under a layout it was not lowered against. A registered statement meets it only after a publication it ran itself; inside a migration, rows a statement returned lazily meet it when a later DDL statement of the session alters a collection those rows still read. Retry the complete statement; the fresh execution binds the published generation.

`COMMIT_APPLY_FAILED_AFTER_MARKER`, `IMPLICIT_ROLLBACK_CLEANUP_FAILED`, `ROLLBACK_CLEANUP_FAILED`, `CATALOG_PUBLICATION_FAILED_AFTER_COMMIT`, `REBUILD_INCOMPLETE`, `REBUILD_REPEATED_FAILURE`, `WAL_WRITE_FAILED`, `WAL_FLUSH_FAILED`, and `PLUGIN_RECOVERY_REQUIRED` are recovery-required exceptions to normal resume semantics. They prove that page apply, eager-state rollback, live catalog publication, index reconstruction, WAL durability, or a plugin's authoritative state did not leave a resumable mutation path. They normally refuse all ordinary MQL and retain only rollback/abort/cancel drain controls plus the direct health diagnostic. A lone `WAL_FLUSH_FAILED` retains the bounded reads listed in [Health](health.md), but it still cannot be cleared in place. Close and reopen so recovery reconstructs trustworthy writable state.

`BTREE_PAGE_REFERENCE_MISMATCH` is `StructuralCorruption`: an index root, child, or sibling reference names a different allocation lifetime from the page it reaches. Reads, writes, and maintenance stop rather than treating a reused page as the referenced index node. The error identifies the affected index domain; preserve the database and diagnostics for recovery or repair.

`PAGE_SCRUB_CORRUPTION` is `StructuralCorruption` the background page scrubber reports for a page whose checksum no longer verifies, before any statement read it. It is filed against the domain the scrubber can attribute the page to, `EngineWide` when the page's owner is not known; restore from a backup.

`BTREE_PAGE_OWNER_MISMATCH` is `StructuralCorruption`: a reached index page belongs to a different owner or rebuild generation. Cold point probes and cached node loads both reject it, even when its checksum and allocation lifetime are valid. The affected index domain is identified for recovery or repair.

`READ_EPOCH_RECLAMATION_STALLED` is a `ContractViolation` raised when a serialized reclamation pass makes no progress at a completion boundary. Shutdown withholds the clean marker rather than certifying unreachable pages as permanently allocated. Preserve the logs and reopen so crash recovery can apply the already-committed Free WAL images with no live readers.

`CATALOG_GENERATION_EXHAUSTED` is a `ContractViolation` raised before a process-lifetime catalog snapshot, structural-conflict, entry, or advisory-dirt identity could wrap. The metadata operation is refused so stale catalog state cannot alias current state and an older enrollment cannot clear newer unpersisted advisory state.

`COMMIT_SEQUENCE_EXHAUSTED` is a `ContractViolation` raised before the positive commit-sequence clock could wrap. The commit is refused without publishing a WAL decision or reusing a durable identity; reads remain available, but the database cannot accept another commit under the exhausted lineage.

`NONCE_COUNTER_EXHAUSTED` is a `ContractViolation` raised before the authenticated-storage invocation identity could wrap. Page and WAL protection are refused; supported key/branch lifecycle handling must establish a fresh nonce domain instead of reusing an AES-GCM identity.

`WAL_ARCHIVE_AUTHENTICATION_FAILED` is `StructuralCorruption`: a protected archive payload failed authentication or canonical framing. The AES-GCM reader rejects nonzero reserved nonce bits, impossible encoded lengths, and trailing protected bytes, including on non-seekable inputs. Recovery refuses that object; use an independently verified archive copy.

Archive key access reports `WAL_ARCHIVE_KEY_MISSING` for ordinary provider availability failures. Cancellation, memory exhaustion, corruption, and simulated process death retain their exception identity through key access; an independent live key-handle cleanup failure cannot replace the access failure. Both causes are preserved in order.

The AES-GCM payload reader likewise preserves cancellation and stronger failures nested inside truncation or cryptographic wrappers. Independent live transform cleanup failures remain alongside the initiating failure in causal order; they cannot replace it with a pool-return error or authentication result.

`TRUNCATE_OUTCOME_INVALID` is a `ContractViolation` raised when a storage provider reports neither the old page count nor the requested cut after a failed truncate. The engine refuses to guess whether the old free-space map and header are safe to restore, so it never re-advertises page identities with an unknown physical lifetime. Preserve the database and diagnostics; this signals a provider bug or external mutation of an open database file.

`ADMISSION_PRESSURE` is a `ResourcePressure` catalog/health code rather than a thrown statement error. It records sustained spill/rejection pressure and is automatically cleared when the admission budget recovers.

`TYPED_INDEX_RECORD_DIVERGED` and `INDEX_REDO_DIVERGED` are `ContractViolation` catalog/health codes rather than thrown statement errors. Each records a `Degraded`, never quarantining, divergence between an index page's logged change and its redo: the first when a commit's typed index-page operations do not reproduce the image it logs, the second when recovery cannot redo an index page and the index is rebuilt from its collection's rows. Statements stay admitted; [Health](health.md) describes what each one switches off and how `ALTER ENGINE RESUME` clears it.

`BACKGROUND_WORKER_STOPPED` is an `Internal` catalog/health/log code rather than a thrown statement error: a background maintenance worker ended on a failure while its engine served, which [Health](health.md) reports as `Degraded`. `CONNECTION_TERMINAL_FAILURE` and `SERVER_LOOP_STOPPED` are `Internal` catalog/log codes of the standalone server rather than statement errors: the row of a connection that ended on a process-terminal failure such as memory exhaustion, and the row of a server loop, accepting connections or certificate renewal, that ended on a failure. The server stops on either ([server log](https://mnemic.io/docs/configuration/#standalone-server-log)).

`ADMISSION_CONFIG_SCHEMA_INVALID` and `CREATEDBY_CONFIG_SCHEMA_INVALID` are `ContractViolation` codes for a compiled-in configuration schema that is missing a field required by its decoder. They indicate an engine build defect; malformed stored configuration rows use structural-corruption diagnostics instead.

`DOCUMENT_PAYLOAD_CORRUPT` means a checksum-valid stored row violates the active schema: its document/Array/Object/polymorphic framing, strict UTF-8, scalar encoding, nullability, virtual-computed-slot NULL invariant, or body primary key is invalid. Any query or maintenance operation that consumes that row stops; malformed fields are never treated as NULL, missing, non-matching, an empty sort key, or a different record. The collection enters structural health quarantine. An unfiltered scalar `COUNT(*)` can use the transactional catalog row counter and is not a body-integrity scan. The lower expression-field decoder also requires exact widths for fixed-width scalars, canonical `0`/`1` Boolean bytes, exact String framing, and strict UTF-8 for synthetic/transformed buffers; it never ignores trailing scalar bytes, manufactures U+FFFD replacement text, or constructs Decimal/date/time values from impossible bit patterns. Durable rows fail at the validator before that defensive decoder is reached. The transactional row counter is recovered from the same WAL commit group as the row mutation; startup does not rebuild it by scanning slots.

`DOCUMENT_PAYLOAD_INVALID` is the corresponding User-class write rejection for the direct binary engine API. It fires before persistence when an INSERT, REPLACE, or temporal version body violates the schema or disagrees with the separately supplied primary key. This includes a direct caller supplying a non-NULL value in any recursive virtual computed slot; no slot, overflow page, or index entry is published and the collection is not quarantined.

`DOCUMENT_SEALED` is a User-class workflow rejection raised inside the claimed engine write boundary. It applies uniformly to direct DML, otherwise-unchanged writes, UPSERT updates, temporal timeline edits, triggers, IVM, plugins/replay, and FK actions. It is not retryable until an authorized writer explicitly unseals the identity. A failed multi-row statement rolls back every earlier row in that statement.

Schema maintenance's internal rewrite allowance expires when that rewrite window ends. Later ordinary writes still require the identity to be unsealed. Callbacks and derived writes receive no rewrite allowance while that window is live. A trigger that mutates a sealed target rejects the schema rewrite and rolls back the migration. Host logging callbacks likewise receive no allowance, including when an enum rewrite logs before replacing its source row. Logger-initiated writes to a sealed row still require explicit `UNSEAL`, even in another database.

`QUERY_METADATA_ALIGNMENT` rejects a metadata-bearing query if its authoritative row buffer and slot-metadata buffer no longer have exactly the same cardinality before aggregation. The engine never guesses which metadata belongs to which row; execution stops and quarantines the affected page-store fault domain instead of returning a plausible but misattributed result.

Every stored slot carries an exact document-layout generation. `DOCUMENT_LAYOUT_GENERATION_UNKNOWN` rejects a row whose generation is absent from the collection's catalog history, while `DOCUMENT_LAYOUT_TRANSLATION_FAILED` rejects a row that validates under its historical schema but cannot be translated through every ordered transition to the active schema. `CATALOG_LAYOUT_HISTORY_MISSING` and `CATALOG_LAYOUT_HISTORY_CORRUPT` reject the corresponding catalog defects before rows are read. These are structural failures: the engine never guesses which schema should decode persisted bytes. `SLOT_PAGE_TYPE_INVALID` and `SLOT_INDEX_OUT_OF_RANGE` likewise reject locators that cannot identify an actual slot on a Data page.

`INDEX_ROW_PREDICATE_MISMATCH` means an index entry resolved a structurally valid live row whose primary key or body values do not satisfy the index condition used by the query. Direct key reads and both buffered and streaming query paths reject the row and quarantine the affected collection or index fault domain. Body-less FK, CreatedBy, pinned-revision, and temporal-history probes also compare the resolved slot-header primary key with the requested id before accepting validity or revision metadata. Identity-wide `SEAL` and `UNSEAL` validate every retained version before changing any state or accepting an already-desired no-op; a pointer to a different primary key is rejected with this error. Temporal co-location likewise validates every retained pointer against the candidate key before relocating any row or accepting a packed-history no-op. `DATA_PAGE_OWNER_MISMATCH` rejects a pointer into another collection's data page, including one that carries the same primary-key bytes. Covered-index plans recompute the leaf key and compare every INCLUDE value with the authoritative live slot before returning leaf-projected bytes; a valid payload copied from another row is corruption, not a result. They never return the row, accept a reference, or silently treat the disagreement as an ordinary non-match. Restore or rebuild from a known-good source before resuming the affected collection.

`COVERED_BLOB_CORRUPT` means covered-row reconstruction rejected malformed key or INCLUDE bytes and quarantines the selected index. Reconstruction scratch exhaustion and cancellation retain their original failure policy instead of creating this corruption report. Existing corruption proofs keep their original code and fault domain, including through cleanup wrappers; modeled process death also escapes unchanged.

`ARRAY_KEY_CORRUPT` means a visited array-index posting has a malformed typed scalar key. Decoding stops and reports the supplying index as the fault domain. The code is registered as `StructuralCorruption` in `[Mnemic].[ErrorCatalog]`. Rebuild the index or restore from a known-good source before resuming. Predicate callback failures keep their own classification.

`COMPOUND_KEY_CORRUPT` means a skip scan found malformed tuple framing, the wrong component count, or a non-canonical typed search component. It fails before that key can direct a seek and quarantines the affected Index fault domain. Rebuild the index or restore from backup.

`INDEX_POINTER_INVALID` means an index entry cannot address a live heap slot: its page is not a Data page, its slot number is impossible, or the slot is tombstoned after exact pending insert state and concurrent-write/relocation races have been excluded. Temporal versions outside `AS OF` and locators known to belong to an unsettled eager insert remain ordinary non-matches. Buffered, streaming, and covered-index execution reject every other stable invalid locator instead of returning a plausible but incomplete result. Do not interpret the error as an empty result; restore or rebuild the affected index from a known-good source.

`BTREE_DUPLICATE_PAIR` means index traversal or explicit certification found the same encoded key and document pointer in more than one equal-key leaf fragment. This is never a legal multimap shape: query-side pointer deduplication could otherwise hide duplicate physical ownership or choose between contradictory covering payloads. Opening, orphan accounting, and destructive cleanup fail closed; preserve diagnostics and rebuild or restore the affected index.

<a id="wal-transaction-structure"></a>

Recovery refuses a checksum-valid WAL whose transaction structure is impossible — records out of strictly increasing LSN order or outside a mini-transaction, interleaved mini-transactions, a duplicate transaction stamp or one that changes inside a mini-transaction, a non-canonical `Begin`, `Commit` or restore-point marker, or a transaction control record before a mini-transaction's end — before an LSN advances or a page is changed. The open fails with a message naming the defect (`Recovery mini-transaction has no canonical Commit record.`); the condition has no code of its own in `[Mnemic].[ErrorCatalog]`. Do not retry or resume in place; preserve the files for diagnosis.

`TRANSACTION_LIFECYCLE_OBSERVER_FAILED` is a health-only structural signal. A rollback-completed or settled observer failed after the transaction outcome was authoritative. Later observers still run, but lifecycle ownership may remain retained, so the engine quarantines rather than certifying normal operation.

`HOOK_MUTATIONLOGSUBSCRIBER_FAILED` reports an ordinary plugin failure during inline observation of a mutation attempt. The engine does not retry the failed subscriber or let it veto the write, and it continues to later subscribers. The event occurs before transaction outcome, so the health row proves neither that the write committed nor that it rolled back, and the callback is no durable change-data-capture or outbox boundary.

The `CHECK_REGISTRY_*_OWNER_*` and `SCHEMA_BARRIER_PUBLICATION_ACQUISITION_MISSING` codes are `ContractViolation` signals. They mean DDL publication lost the durable collection or generation-writer identity needed to update process-local schema state without confusing catalog generations. The operation fails closed; do not treat these as invalid CHECK expressions or retryable schema conflicts.

`MIGRATION_DRAIN_SNAPSHOT_UNBALANCED` and `WRITE_LOCK_COMPATIBLE_LEASE_MISSING` are `ContractViolation` signals for lost concurrency ownership. The former means migration entry released a blocker snapshot it did not own; the latter means DML admission lost the compatible collection write-lock lease needed to bind protected work. Both indicate an engine defect rather than retryable contention.

`INDEX_SCALAR_KEY_ENCODING_SIZE_CHANGED` is a `ContractViolation` signal that the scalar secondary-key encoder disagreed between its sizing and writing passes. Index maintenance stops before publishing a partial or malformed key; this indicates an engine defect rather than a retryable write conflict.

`TEMPORAL_UNIQUE_OWNER_MISSING`, `TEMPORAL_UNIQUE_OWNER_RESOLVER_MISSING`, and `TEMPORAL_UNIQUE_EXTENSION_UNPROVEN` are `ContractViolation` signals that a temporal collection's `UNIQUE` index could not run its valid-time proof ([UNIQUE on a temporal collection](indexes.md#unique-on-a-temporal-collection)): maintenance lost the written version's identity and interval, had no way to read the identity and interval of another version holding the key, or widened a version's interval without its row image. The write stops before the index or interval changes; it indicates an engine defect, never a duplicate value, which reports `UNIQUE_VIOLATION`.

Adding a new code requires emitting it from the detector and registering it in `ErrorCatalog.Entries` in the same commit; drift between the two is a bug.

## Multi-row INSERT refusals name their row

A [multi-row INSERT](dml.md#multi-row-insert) refused because of one of its documents — that document's admission (an unknown field, a type mismatch, a NOT NULL or CHECK violation, a clause its row names for itself whose value is missing or names no instant, whose window is refused or whose actor the collection's attribution refuses) or its write (a supplied or exhausted auto-increment key, a duplicate key, a missing foreign-key target, a trigger body or maintenance failure) — reports the code and class the single INSERT of that document would report, and its message is that statement's message prefixed by `INSERT row <n>: `, where `n` counts the statement's documents from 1. Only `User`- and `Validation`-class refusals carry the prefix. A failure of the statement as a whole — a clause it states once (a validity window on a standard collection), the document or byte cap, cancellation, `WRITE_CONTENTION` after the retry budget, a commit failure, and every corruption or engine failure — carries none, and neither does a single-document INSERT. Every row of a refused statement is rolled back.

```text
INSERT row 3: Duplicate key in unique index ... (UNIQUE_VIOLATION)
```

A client reads the ordinal from the prefix; it is the only position the message format guarantees.

## Usage pitfalls


<a id="pitfall-mql-gotchas"></a>

### Operational troubleshooting

Top failure modes when writing MQL. If your statement compiles but returns the wrong rows, scan this list first.

Statement deadlines are limited to `4294967294ms` (about 49.7 days). `SET STATEMENT TIMEOUT` and `OPTION(TIMEOUT ...)` reject zero, negative, and larger durations with `INVALID_VALUE`, whether the parser reads the literal or a built statement carries it; use `SET STATEMENT TIMEOUT NONE` to clear a session override instead of encoding an effectively-unbounded duration. On TCP, clearing the session override restores `MnemicServerOptions.DefaultStatementTimeout` when configured; it does not bypass the host fallback. Deadline scopes replace their fallback rather than taking the minimum: a longer `OPTION(TIMEOUT ...)` intentionally extends a shorter session or host value for that statement.

Remote authentication does not require a client retry merely because another successful login updates its last-login timestamp. The server synchronizes identity lookup with that update, keeps password hashing outside the catalog gate, and rechecks credentials before accepting the session.

<a id="pitfall-unbounded-scans"></a>

### Unbounded scans

A `FROM [Coll]` with no `WHERE`, no `LIMIT`, and no covering index walks every row. For exploratory queries always add a `LIMIT`. Production queries should hit a registered index — verify with `EXPLAIN`.

<a id="pitfall-when-a-query-returns-0-rows-but-you-expect-some"></a>

### When a query returns 0 rows but you expect some

1. Run `EXPLAIN <query>` — does the plan touch the index you expect? `Strategy` shows the access path. A join appends its physical join tree as `JoinPlan:join:<aliases>` rows (`Scan`, `StreamingLeftDeep`, `MaterializingBushyHashJoin`; `EXPLAIN ANALYZE` names the algorithm that ran, such as `StreamingLeftDeepHashJoin`); `Notes` say how each correlated EXISTS / IN / scalar subquery runs — as the generated `SEMI` / `ANTI` join that actually executes, or per outer row with the reason — and surface "WHERE [X] has no index; CREATE INDEX ..." hints when a FullScan was forced ([EXPLAIN](queries.md#explain--query-plan-introspection)). `EstimatedRows` is `null` wherever no evidence defends a number: statistics-dependent strategies without fresh statistics, and filtered or temporal scans that no statistic estimates; an unfiltered scan of a standard collection reports its document count, point PK / temporal seeks report `1` (`PK IS NULL` reports `0`), and BitmapOr estimates are capped at collection cardinality. If it's 0, the planner thinks no rows match and your query intent likely doesn't reach the data.
2. Strip clauses one at a time. Start with `LIMIT 1` and just `FROM` to confirm rows exist.
3. Check string casing — `'EU'` vs `'eu'` would normally tie via case-fold, but a NUL-byte parameter strips through differently.
4. Check temporal: did you forget `AS OF NOW`? On a temporal collection the default is current-version view; on AS OF it's a point-in-time snapshot. A temporal point seek is available only for equality on the collection's declared primary key; fields literally named `Id` or `DocumentId` are ordinary fields unless declared as that primary key.
5. For joins: did the inner side actually have matching rows? `EXPLAIN`'s `JoinPlan:` rows show which relations each join node reads; run a standalone `FROM [joined].[collection] LIMIT 1` against each.
